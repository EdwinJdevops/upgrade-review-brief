# Deploy the browser review on Render

Status: code/configuration prepared; no live deployment or redeemed credit balance is claimed. The Render account connection is still required.

## Service definition

Use **New → Blueprint** in Render, connect this GitHub repository, and review its root `render.yaml` before deploying. The blueprint creates one Python web service; no database, persistent disk, GPU or background worker is requested.

- Build: `bash render-build.sh`
- Start: `gunicorn wsgi:app --bind 0.0.0.0:$PORT --workers 1 --threads 2 --timeout 180 --no-control-socket --access-logfile -`
- Health: `/healthz`, ready only when the verified model has loaded.
- Compute proposal: `1c-2g` (1 CPU / 2 GB RAM in the current Blueprint reference).
- Automatic deployments: off. Deploy deliberately to avoid unnecessary repeated downloads/builds.
- Session secret: generated by Render; never paste it into the repository, article or chat.

The previous local model experiment measured 1135.6 MiB peak process RSS. Render's 512 MB free compute is below that measurement. The proposed 2 GB instance has **not been proved adequate on Render**. Check actual memory and cold-start behavior before relying on it. Do not claim that the promotional $50 is present, covers all costs or has a particular expiration without checking the account. Review Render's displayed compute cost and remaining credit before creating the service. Scale down or delete the demo after judging if it is no longer needed.

Build preparation downloads approximately 1.1 GB of model weights plus dependencies and a pinned public migration guide. Startup verifies the model files and loads one float32 CPU model. Source/model preparation requires network access; request-time reviews fetch no supplied URLs and call no model API. Use one worker: increasing workers duplicates the model and breaks the process-local concurrency/rate budgets.

## Verification before claiming the category

1. Confirm the service is live and `/healthz` returns `{"status":"ready"}`.
2. Open the home page and run the Kong example. Confirm REVIEW REQUIRED, the readiness path change, five retained passages and model evaluations greater than zero.
3. Review sanitized files through the upload form, then download and inspect both JSON and Markdown.
4. Check that malformed input produces a controlled error and that unavailable inference never returns a keyword result labeled as AI.
5. Record the actual deployment URL, commit, selected compute, observed memory and example result. Only then add Best Use of Render to the DEV article.

The demonstration accepts at most six review attempts per minute globally, one inference request at a time and at most 32 model windows per request. Oversized/unscorable passages remain present and explicitly unscored. Input bodies are capped; temporary files are deleted after the request; logs contain counts/timing rather than input text. The server still receives uploads and trusted hosting operators can access their processing environment. This is a bounded demonstration, not a production multi-tenant service or a privacy certification.

## Local execution

Python 3.12 and a model-capable machine are required. In a virtual environment:

```bash
python -m pip install -r requirements-web.txt
python -m pip install torch==2.14.1+cpu --index-url https://download.pytorch.org/whl/cpu
python -m pip install transformers==4.57.1
python prepare_brief_source.py
python download_reranker.py .models/bge-reranker-base
python -m unittest discover -s tests -v
python verify_web_model.py
gunicorn wsgi:app --bind 127.0.0.1:8000 --workers 1 --threads 2 --timeout 180 --no-control-socket
```

This path does not require WSL specifically. The user can use the GitHub/Render browser setup instead of running these commands.
